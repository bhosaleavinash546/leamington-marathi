# CostVision — 360° review, 6 October 2026

Six independent reviewers swept the tool: CAD-to-cost, the cost engine, PCB, server security, the front end, and the rate data. I verified each finding against the code before acting on it, and fixed what was real and safe to fix before the demo. Everything else is listed below as still open, with its risk. This document is meant to be read before showing the tool to anyone senior.

## 1. Bottom line

**The deterministic costing core is sound.**
- The 8-bucket stack, machine and labour time per part, OEE, overhead and margin on the right base, country re-costing, and traceability all hold up.
- 19 of 19 commodities cost end to end in a real browser.
- The real-parts baseline (40 real CAD parts) is stable.

**What is not ready to claim:**

1. **Accuracy has never been measured against a real price.** `npm run accuracy` has **0 real actuals**: the 5 rows in the file are templates. Every number the tool produces is a reasoned, traceable *should-cost*, not a validated one. This is the single most important thing to say out loud.
2. **The deployed server had serious security holes.** They are all fixed now (§2.1). The worst was that anyone could reset any account's password, including an admin's, when no email server was configured.
3. **The product made claims that were not true.** Examples:
   - a "live / real-time" commodity price feed that is a random-number simulation;
   - an "AI-powered Ornstein-Uhlenbeck forecast calibrated against Bloomberg" that is a straight-line extrapolation;
   - CAD demo results badged as kernel-measured;
   - PCB demo cards labelled "computed live" that showed fixed numbers;
   - stale software-cost figures and an accuracy figure better than the engine's own back-test.

   All are now corrected in the product text (§2.5).
4. **The rate data has inconsistencies that move costs by 5–30 % on some grades** (§3.3). Rates may only change through the dated rate refresh, so these are reported here, not edited.

## 2. Fixed in this review (with root cause)

### 2.1 Security

| # | Finding | Root cause | Fix |
|---|---|---|---|
| S1 | **Anyone could take over any account** with no SMTP configured: `/resend-otp {purpose:'reset'}` returned the reset code in the response. The same leak let anyone sign up as a listed admin address before its owner and receive admin rights. | `devOtp` was returned whenever SMTP was unset, which was meant for a laptop install but is also the default on the public deployment. Admin promotion ran at sign-up, before email verification. | The code is returned only to a **same-machine** request with no proxy header, or with an operator's explicit `CV_SHOW_DEV_OTP=1`. `purpose` must be `signup` or `reset`. A code is burnt after 5 wrong guesses. Admin promotion requires a verified account. |
| S2 | Any signed-in user could make the server read **any file** (`/app/.env`, the database) or crash it with `/dev/zero`, through `POST /api/dfm/jobs {filePath}`. | The request's path went straight to `readFile`. | Only a file this server staged (`cv-dfm-<uuid>.<ext>` in the temp folder) is accepted. |
| S3 | CAD tessellation ran **without sign-in**, giving anonymous use of the 2-worker kernel and up to 250 MB uploads. | `requireAuth` was missing on that one route. | Added. All in-app callers already send the session. |
| S4 | Any account could **replace the shared rate library** (`PUT /api/sync/library`) or **override global material prices** (`PATCH /api/prices/override`), or spend the metal-price API quota. | Only "signed in" was checked, and anyone can sign up. | Admin-only. No UI calls these routes. |
| S5 | The `.env.example` placeholder JWT secret was accepted in production, so anyone who read the example could forge sessions. | Only a missing secret was refused. | The placeholder is treated as unset. A short secret gets a warning. |
| S6 | Stored XSS from imported scenario names, assembly names, comparison warnings and news links. (The PCB panels were reported as raw too, but the screen escapes the whole result once (`escapedForDisplay`) before any panel builds: a false positive. Adding a second escape there broke the smoke test's "text shown literally" check, so it was reverted.) | `innerHTML` with unescaped text. | Escaped at each real sink. News links must be `http(s)`. The ASIL badge's own second escape ("R&D" shown as "R&amp;amp;D", and "$&" re-inserting text) is removed. |
| S7 | `/reprice` threw and left the request hanging. Mixed-case sign-up crashed on a UNIQUE error. Malformed `decisionAnswers` gave a 500 after the kernel had already run. The PCB stream hung on a malformed OCR reply. | Express 4 does not catch async errors, and the inputs were not normalised. | try/catch, a lower-cased email, guarded parsing, array guards. |

### 2.2 Cost engine

| # | Finding | Effect | Fix |
|---|---|---|---|
| E1 | The Monte-Carlo band added overhead and margin to **bought-in** content, which the headline excludes. | On a BIW assembly the band centred about +15 % above its own headline: the "range" did not contain the answer. | Same carve-out as `core.ts`. |
| E2 | The "coverage-guaranteed" conformal band scored errors against the *actual* price but applied them to the *estimate*. | Every under-estimate fell outside its own "guaranteed" band, and a large error gave a negative lower bound. | Scored against the calibrated estimate; low bound ≥ 0. |
| E3 | **Casting melt loss was credited back as scrap.** | Lost aluminium was charged at about 82 % of its price. | `lossIsNotScrap`. The casting bracket moves +£0.03 and the stub axle +£0.04; baseline re-recorded. |
| E4 | NaN or Infinity in consumables, energy or bought-in gave a NaN or ∞ total with no error. | | Validated. |
| E5 | The sensitivity tornado listed a shared labour or machine rate **once per operation**: four identical bars. Material utilisation appeared twice, and one copy *raised* cost at +10 %. | A misleading chart in a demo. | One bar per rate, naming the operations that share it; duplicate removed. |
| E6 | The gear induction coil, broach and inspection master stayed at the UK £ in every country. | | × the toolroom factor, as the fixture beside them already was. |

### 2.3 CAD to cost

| # | Finding | Fix |
|---|---|---|
| C1 | An inch model answered "inch" was **measured at 25.4×** but its sheet blank was **unfolded at 1×**, so the blank was about 1/645 of its true area. | The unit scale is passed to the skin-mesh kernel. |
| C2 | The kernel's timeout was a `TimeoutError`, which every analysis step's `except Exception` swallowed. A slow part came back as **"success" with wall, topology or draft silently missing**. | A `BaseException` timeout passes the step guards and is reported as `code: 'timeout'`. |
| C3 | The analysis cache ignored the **file name** (material and part evidence), the **FASTBLANK DXF** and the **active company rate book**. A re-upload or an admin's rate change served a stale result. | All three are in the key. `CAD_PROMPT_VERSION` 51. |
| C4 | In AI mode the screen showed "Est. total/part": the AI ballpark plus the kernel's face-count tooling, which costing deliberately does not use. The PDF printed an unlabelled "Cost range". | Labelled "AI ballpark … not the should-cost" on both. |
| C5 | AI autofill wrote **overhead %, margin %, weight and volume** from free text into the cost inputs, numbers the model could invent. | A number is filled only if the user actually wrote it. |

### 2.4 PCB

| # | Finding | Fix |
|---|---|---|
| P1 | Re-analyze sent **every BOM row** as an engineer correction. The whole BOM became "engineer-priced", the "to verify" bucket emptied, and lines without a designator (`—`) collapsed into copies of one line. | Only changed or pinned rows are sent. Placeholder designators are keyed by part number + description. A typed 0 is now allowed. |
| P2 | A hedged part number ("assumed TLF35584", "… or similar") resolved to a **confirmed catalogue price**. | Hedges and `?` / `~` are refused. The line stays a range, flagged to verify. |
| P3 | A model-written "-Q1" suffix could flip the board to **automotive**, adding IATF and class-3 premiums and NRE. | Only codes from the supplied BOM file or confirmed by an OCR marking count. |
| P4 | Order quantity: "1e7" was read as **1** (a prototype costing), and 0 or negative values passed through. | `parseOrderQty`: 1 … 10,000,000, default 100. |
| P5 | The PDF and Excel "to verify" list used a different rule from the screen. | Both use the server's flag. |

## 3. Still open (not fixed), ranked

### 3.1 Must be said at the demo

1. **No validation against real prices.** No actuals have been logged, no PCB board has been labelled, and nothing has been compared with a price JLR paid. Treat every output as a should-cost to discuss with a supplier, not a target to impose.
2. **PCB photo-reading accuracy is unmeasured.** The model reads chips and writes the parts list. Prices are bounded by class ranges and the catalogue, but identification is not measured.

### 3.2 Security and platform (fix before any wider rollout)

- **Open sign-up.** Anyone can create an account, and "signed in" is the only gate on most data and on AI spend (per-user rate limits do not cap the total). Recommendation: invite-only or SSO on the public deployment.
- **No tenancy.** Supplier quotes and BOMs are shared across all users; the tables have no owner column. That is fine for one team; it is wrong for several.
- **Resource limits:**
  - the PCB uploader can take about 49 × 20 MB in memory;
  - upload and mesh caches have no size cap;
  - `uncaughtException` is swallowed;
  - some error replies echo upstream messages;
  - the sign-in lockout can be used to lock out a known user;
  - the user's name is not escaped in OTP emails;
  - `xlsx@0.18.5` has known CVEs (admin-only upload);
  - the CSP allows inline script.

### 3.3 Rate data (change only through `scripts/rate-refresh.ts`)

### 3.4 Engine and model choices to settle

- **Die count.** HPDC, sheet metal and moulding round die sets **up** (`Math.ceil`); forging, rubber, blow and roto moulding are fractional. One rule should apply everywhere. Example: 120k parts on a 100k-shot die charges 2 dies, against 1.2 fractional.
- **Possible energy double count.** Thermoforming oven energy and extrusion melt energy are charged per kg *and* may already sit in the machine-rate build-ups. This needs the build-ups audited.
- **Fallback country table.** When the exact re-costing is unavailable, the linear table's overhead and margin are not normalised for a non-UK source. The main path (exact re-costing) is correct.
- **Feature-costing card.** It puts a full setup into every part's time; the card only, not the headline.

### 3.5 CAD and PCB pipeline

- **Bulk vs screen.** A bulk run applies neither the units question nor blank development: an inch model in bulk is costed at the wrong scale.
- **STL limits:**
  - STL parts cannot use Re-analyse (no geometry hash), so answering a question asks you to upload again;
  - STL meshes are not checked for being closed.
- **Overrides ignored.** In deterministic mode the weight, volume and density override fields do nothing.
- **Process budget.** Up to 4 kernel processes can run on a 2 GB VM.
- **Before the cache lookup.** Blank development runs even when the result is already cached.
- **Timeouts.** The screen times out at 120 s; bulk allows 300 s.
- **PCB re-price after re-analyze** can apply the volume factor again to typed prices.
- **Model specs reported as measured.** A model-asserted "measured" board size is printed as measured. Coating, copper weight and board weight from the model are not verified.
- **Live distributor price breaks** are chosen on board count, not parts bought. Only about 5 part numbers are actually queried on automotive boards.
- **ASIL guard.** It accepts description words ("SBC", "lock-step") as safety hardware.
- **OCR tick.** "Read off the chip ✓" survives a model-extended suffix (TJA1044 → TJA1044GTK/3Z).

### 3.6 Front end

- **£ in other currencies.** Literal £ remains in the PCB analysis panel (about 40 places), result warnings, the face-cost legend and the software cost panel when another currency is selected. Share links always show £.
- **Negotiation model.** It uses fixed 12 % overhead and 8 % margin, not the costing's own.
- **Code structure.** `main.ts` is still about 20k lines.

## 4. Improvement areas and advanced features

**Highest value first:**

1. **Close the accuracy loop.**
   - Import purchase-order prices (CSV or ERP), match them to costings by part number, and switch calibration on by default.
   - Show MAPE and bias per commodity on a dashboard.
   - Without this, the tool cannot earn trust beyond its arithmetic.
2. **Governed rate refresh.** Scheduled index pulls (LME, Eurostat, Fastmarkets where licensed) into a review queue, alloy-content drivers for every derived grade, and one FX source.
3. **Enterprise basics.**
   - SSO (OIDC/SAML), invite-only, roles, and workspaces with tenancy.
   - An audit trail per costing: inputs, rate-book hash and versions, with a signed PDF.
4. **STEP assemblies.** Read the assembly tree, cost each child, roll up the bought-out and made parts.
5. **Design-to-cost.** Cost impact per feature: the face-cost heatmap exists, so add "what if this wall were 2 mm" and DFM savings ranked by £.
6. **Supplier quote teardown to negotiation pack.** Line-by-line deltas against the should-cost, with the drivers and the evidence.
7. **PCB evaluation set.** Ten labelled boards (photo + true BOM + PO price), to measure identification and price accuracy before relying on the photo path.
8. **EV content libraries.** Battery cell, module and pack; e-motor; inverter, as rate-backed modules rather than one-off studies.

## 5. Demo guidance

**Show:**
- CAD-to-cost on a real STEP file, on a machine with the OCP kernel;
- the 8-bucket build-up and its traceability;
- the country comparison, which re-costs the part in each country;
- the material picker;
- the Excel/PDF reports.

**Avoid presenting as evidence:**
- the commodity ticker or its forecast;
- the PCB demo cards;
- any accuracy percentage for hardware should-cost (there is none yet).

**Say:** "Every number is traceable to a dated rate and a stated rule. We have not yet validated it against our purchase prices — that is the next step, and the tool is built to learn from them."
