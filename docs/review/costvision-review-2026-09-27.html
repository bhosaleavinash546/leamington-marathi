CostVision review

The costing engine is well built and well tested. The problems are around it: how the server protects data, the default values every user sees first, one gap in how CAD parts get routed, and a product identity that still says "AI" in a build that has AI switched off. None of these is hard to fix. Several should be fixed before anyone outside the team uses the tool.

1 critical 8 high 11 medium 17 low

Every finding below was reproduced by running the tool: live API calls against an isolated database, the browser driven through all 22 commodity tabs and 8 pages, an automated accessibility audit, exports opened and reconciled, and the full test suite run with and without the geometry kernel. Where something was checked and turned out fine, it is listed under "Checked and ruled out".

Fix these first

In this order. The first four are small changes with large consequences.

  1. Load the settings file before anything reads it. One line in server/index.ts. Today a native start ignores the real session secret and several other settings. C1
  2. Require sign-in on every data route, and fail closed when no team key is set. Saved scenarios and supplier quotes are open to anyone who can reach the server. H1 H2
  3. Bind the laptop package to 127.0.0.1. It currently listens on every network interface. H3
  4. Escape PCB bill-of-materials fields before rendering them. Markup in an uploaded BOM file reaches the page as HTML. H6
  5. Make each commodity's default tooling volume match its default annual volume. The tool's own audit flags its defaults as wrong on 17 of 20 commodities. H4
  6. Offer casting and forging in the route question when the measured wall is thick. Then make the regression baseline answer only with options a user can actually pick. H5
  7. Remove accuracy claims that have no data behind them. Stop the accuracy report pooling example rows into a "high confidence" figure. H7
  8. Decide whether the PCB fabrication table is a price or a cost. Then stop stacking overhead and margin on it if it is a price. H8
  9. Fix the Assembly tab error, and say "AI is switched off" in the no-AI build. Also reconcile the uncertainty band with the confidence label. M1 M2 M3
  10. Accessibility quick wins. Name the region and currency controls, raise the primary button contrast, and let Escape close dialogs. M10

What is working

Verified during this review, not taken from documentation.

Tests. 2,338 of 2,338 pass, including with the real OCCT kernel installed. The real-parts baseline re-measures the actual STEP files and still reproduces its recorded costs.
Build. Typecheck and production build are clean. The committed dist matches the source.
Stability. No JavaScript errors on any of the eight main pages. No sideways scrolling on desktop or at 390 px phone width.
Keyboard. Focus is visible on every stop, in a sensible order, with clear labels on the navigation.
Motion. Eight short transitions, none looping, the longest 580 ms. All of them stop when the viewer asks for reduced motion.
Exports. Excel and PDF both reproduce the on-screen total to the penny (£9.34). The workbook carries six sheets, including a traceability sheet.
Air gap. With AIR_GAPPED=1, model calls throw. The CAD path asks the engineer for route and material instead of guessing.
Database access. Queries use bound parameters. Both dynamic updates whitelist their columns.
Laptop package secret. The Windows launcher and Docker both pass the session secret correctly. The critical finding below does not affect them.
Self-audit layer. The tool's own audit caught the default-value problem in H4. The idea is sound; the defaults are what need fixing.

Security and data

CriticalC1

A native start signs sessions with the public default secret

ES module imports run before the module body. So the auth middleware reads JWT_SECRET before config() loads .env, finds nothing, and falls back to the default written in the source. The startup banner and /api/health still report the secret as configured.

Proof
A token signed with should-cost-dev-secret-DO-NOT-USE-IN-PRODUCTION was accepted by /api/auth/me and by the admin-only /api/rate-library/status (200). The middleware trusts the token payload without a database lookup, so any made-up user id works on non-admin routes.
Affected
make start, npm run server, npm run dev:full. Not affected: the Windows package and Docker, which set real environment variables before Node starts.
Also ignored
Every setting read at import time: TEAM_API_KEY, the SMTP settings (so sign-up and password-reset emails), CV_DATA_DIR, PYTHON_BIN, upload limits.
Where
server/index.ts:7 and :32, server/middleware/auth-middleware.ts:9–17
Fix
Make import 'dotenv/config' the first line of server/index.ts. Have the health check report the secret the middleware actually uses.
HighH1

Anyone who can reach the server can read, add and delete every saved scenario

The sync routes allow everything when no team key is configured (if (!TEAM_KEY) return true). The Windows launcher never sets one. The UI silently copies every saved scenario, with its full inputs and cost results, to this endpoint.

Proof
With no credentials: POST a scenario, 200. GET returned it. DELETE, 200.
Where
server/routes/sync.ts:8–11, src/ui/main.ts:17729
Fix
Put requireAuth on the router, scope scenarios to their owner, and refuse requests when no team key is set.
HighH2

Supplier quotes can be created and listed without signing in

Eleven route files have no sign-in check at all: quotes, bom, rfq, pcb, prices, telemetry, aichat, agent, sync, commodities and news. The last two may be meant to be public. The others hold commercial data or spend AI credit.

Proof
With no credentials: POST /api/quotes returned 201, and GET listed the new quote. The chat and agent routes answered too; they only refused because no AI key was set.
Fix
Mount requireAuth on each router in server/index.ts. List any route that is deliberately public in one place.
HighH3

The server listens on every network interface

app.listen(PORT) binds to 0.0.0.0. Together with H1 and H2, the machine's firewall is the only thing between the network and the saved costings.

Proof
The scenario endpoint answered 200 on the container's network address, not only on localhost.
Fix
Bind to 127.0.0.1 by default, with a HOST setting for deliberate server installs.
HighH6

Markup in an uploaded BOM file is rendered as HTML

parseBOMFile keeps a description such as <img src=x onerror=…> unchanged. The PCB panel then puts reference, description, package, value, part name and limitation text into the page without escaping. The security policy allows inline handlers, and the session token lives in localStorage, where a script can read it.

Proof
Parser output confirmed directly, and template lines confirmed unescaped. Not fired end to end in a browser.
Where
src/ui/main.ts:8590–8594, :8606, :8615
Fix
Wrap each field in escHtml(), which the file already uses 242 times elsewhere.
MediumM4

Sessions cannot be revoked

The middleware accepts any validly signed token for seven days without checking that the user still exists or isn't locked. A deleted or locked account keeps working until its token expires.

Where
server/middleware/auth-middleware.ts:25–33
Fix
Look the user up on each request (the admin check already does), or keep a short token life with a revocation list.
MediumM5

No rate limit on the AI routes

aichat, agent and pcb have no limiter, and there is no global one. This doesn't matter while air-gapped. It matters for Option 3, where each call costs money.

MediumM6

Ten production dependency advisories, five of them high

  • xlsx 0.18.5: prototype pollution and ReDoS. There is no fix on npm; SheetJS publishes fixed builds on its own CDN. This library parses uploaded rate cards.
  • nodemailer, express-rate-limit (via ip-address), pptxgenjs (via image-size): high. body-parser, qs, dompurify, morgan: moderate.
  • Development only: vitest (critical, UI server), vite (path traversal in the dev server).

Costing correctness

HighH4

The shipped defaults fail the tool's own audit on 17 of 20 commodities

Every default form states an annual volume of 10,000 but amortises tooling over anything from 2,000 to 500,000 parts. The tool's self-audit marks this HIGH on its own first screen, with per-part tooling out by between 0.2× and 50×. It's the first thing a new user or a director sees.

Fix
Set each default amortisation volume to annual volume × a stated programme life, and show that life on the form.
HighH5

The route question leaves out casting and forging for thick-walled sparse parts

Below 20% fill, the question always offers sheet metal, injection moulding or machining, whatever the measured wall. The question's own explanation says "the same shape is cast at one volume and machined at another" — then offers no casting option.

Proof
Three of the five real production parts get only those three options: the steering knuckle, Casting_Braket and PRCR002, all with 9–15 mm walls. The engine accepts cast_and_machine when sent directly (it moves on to the next question), but the screen never offers it.
Masked by
The real-parts baseline answers two of these parts with cast_and_machine, an option users are never shown. It answers the knuckle with machining, although its own note says the knuckle is forged in production. The regression net passes on paths no user can reach.
Where
src/engine/cost-input-rules/derive/commodity.ts:202–206, scripts/real-parts-baseline.ts:61–83
Fix
Use the measured bulk wall to filter routes: above about 6 mm, drop sheet metal and injection moulding and add casting, forging and cast-and-machine. Assert in the baseline that every answer is one of the options offered.
HighH7

Accuracy figures are shown with no data behind them

The accuracy dataset is five rows, each marked "EXAMPLE — replace with real quote". The report still prints ALL: 5% MAPE, confidence high, because pooling one or two example points per commodity crosses its five-point threshold. The executive deck claims "±8% typical model accuracy" and "10× faster than manual costing".

Where
scripts/accuracy-samples.csv, src/engine/accuracy.ts:57–62, build_pptx.py:618–620
Fix
Remove the claims until real estimate-and-actual pairs exist. Make the report skip rows marked EXAMPLE, and don't let the pooled row claim confidence that no single commodity has earned.
HighH8

PCB fabrication adds overhead and margin to a figure documented as a price

The base is "Base panel price (£) for 500×600 mm 2-layer FR4". The whole board cost enters as one line on material with no operations, and then gets 12% overhead and 8% margin. Default: £82.43 becomes £100.75, which is ×1.22. Conversion shows £0.00, and the tool's own audit says "the estimate is a purchase price, not a should-cost". The ±0.1% band on this result is covered under M2.

Where
src/engine/modules/pcb-fab.ts:64–65 and :340–360
Fix
Either model fabrication as operations (imaging, etching, lamination, drilling, plating, test), or treat the table as a price and set overhead and margin to zero for this commodity. Either way, label it.
MediumM1

The Assembly tab throws an error and shows the previous commodity's result

Switching to Assembly BOM raises Cannot read properties of null (reading 'querySelectorAll'). The result panel keeps showing £31.86 from Wiring Harness, including the text "Uncalibrated for wiring harness".

MediumM2

Uncertainty bands collapse where cost enters as one figure, and contradict the confidence label

PCB fab shows ±0.1%, PCBA ±0.3% and BIW ±0.8%, each described as a "tight band" — next to "Low confidence" on the same result. The Monte Carlo run samples only the small part of the cost that isn't a single fixed figure, so the band shrinks exactly where uncertainty is largest.

Fix
Sample the direct-cost figure too, with a spread set by its confidence, or show no band when most of the cost isn't sampled.
MediumM9

The overhead base isn't the Factory Cost shown on screen

Overhead is 12% of material + process + labour + tooling. The Factory Cost on screen also includes packaging and logistics, and the report just says "12% of factory base". On the machining default, 12% × £7.77 shown = £0.93, but the overhead line reads £0.88. The engine's choice is defensible; the labelling makes a correct number look wrong.

Where
src/engine/core.ts:253–255
Fix
Show the overhead base as its own line in the breakdown, the PDF and the workbook.
LowL7

A CAD upload is offered on commodities the CAD path can't cost

11 of 20 commodities can be costed straight from a CAD file. Sheet-metal fab, extrusion and composites still show "Upload CAD to auto-fill this form", even though none of them can be costed from CAD.

Interface and experience

MediumM3

The no-AI build keeps asking for an AI key

With AIR_GAPPED=1 on the server:

  • The chat replies "Add it in Settings or set the ANTHROPIC_API_KEY".
  • Every result shows "AI assistant requires an Anthropic API key".
  • The home page leads with two AI start cards and a chat bubble.
  • /api/health doesn't report the air gap, so the interface can't know about it.

For JLR, this tells users to do the one thing the policy forbids. The air gap itself holds: the routes check for a key before they check the air gap, so users get the wrong message.

Where
server/routes/aichat.ts:34–36; the same pattern in agent.ts and pcb.ts
Fix
Report airGapped from the health check. Hide AI entry points and replace the messages with "AI is switched off in this installation".

Accessibility and motion

MediumM10

Four accessibility failures that repeat on every page

  • Unnamed controls. The region and currency selectors (#mfg-region-selector, #currency-selector) have no accessible name, so a screen reader says only "combo box". axe rates this critical, and it appears on all eight pages.
  • Primary button contrast. "Start a costing" and "New Costing" are white on #38bdf8 at 2.14:1. WCAG requires 4.5:1 for normal text, and even large text needs 3:1.
  • Help Centre. Escape doesn't close it, and its ✕ has no label or title.
  • Label mismatch. The visible text "New Costing" has the accessible name "Start new should-costing", so a voice-control user saying "click New Costing" gets nothing (WCAG 2.5.3). A popover (#cv-popover) also has no accessible name.
Good

Motion is handled properly

No looping animation, nothing longer than 580 ms, and every animation stops under prefers-reduced-motion. The phone layout at 390 px is well done.

Advanced features worth adding

Read tolerances and GD&T from the STEP file fits the no-AI policy

STEP AP242 can carry semantic tolerances, and OCCT reads them through its XCAF tools. That gives tolerance-driven machining cost without anyone reading a PDF drawing, so it needs no AI approval.

Developed blank and nesting for sheet metal and BIW researched

The prototype matched a hand calculation to 0.001% on a bent part and a textbook drawn-cup blank to within 0.62%. Nesting two interlocked blanks raised material use from 71.7% to 94.6%. The FastBlank DXF import already exists.

Validation against real JLR actuals unblocks H7

Replace the five example rows with CAPPe and FastBlank results, and purchase orders. Report error per commodity, and publish a number only once it's earned.

PLM hook

Re-cost a part automatically when its CAD is checked in or an engineering change lands, so costs don't go stale between reviews.

Approval and audit workflow

Submit, review, sign off, with locked versions and a readable change history between versions.

A real commodity index feed

Commodity prices are currently a seeded random walk labelled "indicative". Connect a licensed index or JLR's own purchasing data, with indexation clauses.

Better carbon

Per-commodity process energy and supplier grid mix, reported beside cost the way the three tools above present it.

BIW press process

Tandem and transfer lines, draw-panel addendum and binder, tailor-welded blanks, and a separate blanking-line operation.

It dismisses itself after a few seconds, and measured, it overlaps no button on desktop. On a phone it briefly covers the header.

Fine

Low contrast on the headline word "cost"

That was the tour's dimmed backdrop in an early screenshot. Without the tour, it renders in readable violet.

Fine

The open sync route writes row default; costing reads row company. The route is still open (H1), but it doesn't change the rates that price parts.
