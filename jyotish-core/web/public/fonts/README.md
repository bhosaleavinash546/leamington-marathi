# Self-hosted faces

Generated by `npm run fonts:subset` (`tools/design/subset_fonts.py`). Do not edit
by hand — regenerate, so the codepoint set stays derived from what the app can
actually emit rather than from memory.

All three families are licensed under the **SIL Open Font License 1.1**, which
permits self-hosting and subsetting. The OFL requires that the licence travel
with the fonts; the full text is at <https://openfontlicense.org/>.

| Family | Designer / foundry | Roles | Files |
|---|---|---|---|
| Mukta | Ek Type | body, UI (`--font-body`) | `mukta-{devanagari,latin}-{400,600}.woff2` |
| Rozha One | Ek Type | display, masthead (`--font-display`) | `rozha-one-{devanagari,latin}-400.woff2` |
| IBM Plex Sans Devanagari | IBM / Bold Monday | tabular data (`--font-data`) | `plex-deva-{devanagari,latin}-{400,600}.woff2` |

`NotoSansDevanagari-Variable.ttf` is a separate concern: it is the face
WeasyPrint embeds for PDF export (`render/pdf.py`), also OFL-1.1, and it is not
served to the browser.

## What the split means

Each family ships as two files with disjoint `unicode-range` declarations in
`web/app/tokens.css`, so an English page never downloads the Devanagari payload.

The Devanagari files carry the **whole** of U+0900–U+097F plus ZWNJ and ZWJ, not
just the characters in `locales/`: the `name` field is arbitrary user Devanagari.
The Latin files carry every character in `locales/` plus the marks the formatters
generate (`°`, the ASCII arcminute and arcsecond, separators, both digit sets).

The declared `unicode-range` says exactly what each file contains and no more. A
range claiming coverage the file lacks is worse than no range at all: the browser
picks that face and draws a missing-glyph box instead of falling back.

Two faces exceed the 90KB per-face budget in DESIGN.md §9 — see
`docs/design/DIRECTION.md` §4.3, which states the overage and the options.
