1Summary

The KPI dashboard is a shared, read-only view of every costing saved to it — by every signed-in user — consolidated in GBP. It answers four questions for management: what the costing covers, what filters are on, how big the potential opportunity is, and where to act. Engineers use the same page to find, check and open individual costing records.

−£4.03Unfavourable gaps — 2 records below should-cost
£264.0kAnnualised — 1 record with an admin-validated volume

(Figures from the demo data in the screenshots.) Five rules make the numbers trustworthy:

  • No figure is computed on the screen. One reporting model on the server produces every KPI, chart, table, insight and export.
  • Each costing counts once. A part is identified by its part number; the same part on the same programme, model year and powertrain is one "application", and only its newest costing counts in the money KPIs. Older revisions and other users' duplicate costings are kept, labelled, for activity.
  • Money is converted honestly. Each value is converted to GBP at its own frozen exchange rate; a missing cost is never treated as zero; current and should-cost are only compared on the same delivery terms; different currencies are never added together.
  • A gap is not a saving. The opportunity is a sum of per-piece gaps; it becomes an annual figure only where an admin has validated the annual volume. Validated and implemented savings are tracked separately.
  • Everything is traceable. Original values, the FX snapshot, the source tool and owner stay on every record; every change is in the audit log; the Excel export re-adds the KPIs with live formulas.

2Where it lives and who sees what

The dashboard is the KPIs item in CostVision's left navigation (gauge icon). It loads on first open and keeps its filters for each person between visits.

WhoCan do
Every signed-in userSee every eligible costing record from every user (read-only), all filters, charts, drill-down, records, the record panel and all three exports.
The record ownerEdit their own record: part number, programme, model year, powertrain, current cost, annual volume, notes, status draft / completed; delete it.
An administratorEverything above on any record, plus: mark reviewed / approved, validate an annual volume, set a saving status, mark test records; load approved FX rates, choose the FX policy and run a controlled recalculation; import CSS System / CPSC II records; read the audit log; see excluded records.
Not signed inNothing — every dashboard request needs a session (HTTP 401).
Who may see what was decided when the dashboard was built: all signed-in users see all eligible records. It assumes sign-up is limited to JLR accounts (planned in the Phase 1 readiness build).

6Where to act and insights

Directly under the KPIs, the two charts that answer "where is the money, and where is coverage missing".

  • Potential cost opportunity by commodity — ranked bars of the per-piece opportunity. Click a bar to filter to that commodity.
  • Commodity × programme — a coverage map: each cell is the number of current costings, darker = more; hover shows the opportunity; click a cell to filter to both.

Insights are written only from what the data shows: most activity, largest opportunity, programme and powertrain coverage, commodities with fewer than 3 current costings, applications with a gap of 15% or more, records awaiting review and the last 30 days of activity. The thresholds are printed on the page. "Filter to this" applies the matching filter.

8Drill-down

A table that steps down one level per click: commodity → programme → powertrain → model year → component → costing record. Each level shows current records, eligible records, GBP current, GBP should-cost, GBP gap and opportunity. Breadcrumbs step back up. Active filters stay applied throughout, and the records table below follows the drill path.

The path is also shown as a chip, "Drill-down (table and exports)", with its own × to leave it. Exports apply the commodity, programme, powertrain and model-year levels; a component level is shown on screen only (the export says so) so that the workbook's reconciliation always compares the same set of records.

10The record panel

  • Classification: commodity, programme, model year, powertrain, country, owner, costing date, last update, original record id, annual volume (and whether it is validated).
  • Cost: current cost and should-cost each in the original currency, delivery terms, GBP value and the frozen FX snapshot (rate, source, effective date, method, when frozen, approved or reference); the gap and gap % or the reason it is not compared.
  • Other costings of this application: older revisions and other users' duplicate costings, each one click away.
  • Original costing analysis: the saved CostVision costing (8-bucket breakdown and operations) read-only; for imported records, the tool and its record id.
  • Copy link: a link (…/calculator/#kpi-record=<id>) that opens CostVision straight on this record.
  • FX history: every earlier snapshot an admin recalculation replaced (owner and admins).

11Currencies and FX

GBP is the reporting currency. Each value keeps its original amount and currency; its GBP equivalent is that amount × the GBP-per-unit rate frozen on the record when it was saved. The current cost and the should-cost are converted independently, then the gap is worked out.

TopicHow it works
CurrenciesAny ISO 4217 code the platform knows (not a fixed list). A code that is not ISO 4217 makes the record invalid (excluded, listed for admins).
Default policyApproved monthly rate for the costing month (decided 11 Nov 2026). Alternatives an admin can choose: rate in force on the costing date, or the latest loaded rate.
Approved ratesLoaded by an admin from a CSV / Excel file (GBP per unit, or units per £1 converted automatically), each with its source.
Before rates are loadedThe built-in rate-book reference rates are used and labelled "reference, not approved" everywhere (cards line, table "ref" mark, record panel, exports).
Never 1:1A currency with no rate is "No FX rate" and left out of the money KPIs — never converted 1:1.
FrozenLoading new rates or changing the policy changes nothing until an admin previews and applies a recalculation; the previous snapshot is kept in the record's FX history.
GuardA rate more than 10 times away from the reference is refused (almost always an inverted rate), naming the row and column.

The Original currency switch replaces the GBP financial position with one row per currency — records and sums of current cost and should-cost, and the gap where both are in the same currency and terms. Currencies are never added together; charts stay in GBP.

12Data quality and the counting rules

RuleEffect
ExcludedDeleted, test or invalid records (bad currency code, negative cost, no name or date) are in no KPI or chart; counted here and listed for admins.
IdentityA component is its part number (upper case, spaces removed). An application = part number × programme × model year × powertrain. Names never merge records; a record without a part number stands alone and is flagged.
Current recordThe newest non-draft costing of an application (the newest draft if all are drafts).
Older revisionA costing its own owner has since revised — kept for activity, not in money KPIs.
Duplicate candidateAnother user's costing of the same application — kept, labelled, not in money KPIs.
Financially eligibleA current record with both costs, both converted to GBP, on the same delivery terms (DAP / EXW).
Missing valuesNever treated as zero; counted under their reason (missing current cost, should-cost, FX, different basis).
Order of workThese rules run on all records BEFORE filters, so a filter can never turn an old revision into the current one.

The one-line summary at the top of the page ("5 of 7 current records compared in GBP · 1 without a current cost · 1 on a different delivery basis · 1 duplicate candidate") links to this table.

14Administration

The Admin button (administrators only) opens three tabs.

TabWhat it does
FX rates & policyChoose the default FX policy; load approved rates (CSV / Excel: currency, period YYYY-MM or YYYY-MM-DD, gbp_per_unit or units_per_gbp, source) — the whole file is refused on any error, naming row and column; list loaded rates; preview a recalculation (what would change, old v new GBP and rate source) and apply it (the old snapshot is kept on each record).

Required: source tool, source record id, owner, component, status, costing date. Re-importing the same tool + id updates the record. Refused on any error, naming row and column.
Audit logThe last 200 changes: save, edit, delete, FX load, policy change, recalculation, import — with who and when.

15Getting data in

From CostVision. Cost a part with any commodity tool or CAD to COST, then More → Save → Save to KPI Dashboard. The details step shows the should-cost from the costing (read-only, with its delivery terms and country) and asks for what the costing does not hold:

  • Part number (required — it identifies the component and links revisions), component name, programme, model year, powertrain;
  • status draft or completed (reviewed / approved are set by an admin);
  • an optional current cost per piece in its own currency, with its delivery terms and source (quote, purchase order, contract);
  • annual volume (counts in the annualised figure only after an admin validates it) and notes.

Saving again for the same part, programme, model year and powertrain makes a new revision; the newest becomes current automatically.

From CSS System and CPSC II. Their data structures are not available to CostVision, so records arrive through the admin import (section 14). The template's column list is the interface; once JLR supplies each tool's export columns they can be mapped to it.

16Themes, screens and states

The dashboard follows CostVision's light and dark (black + green) themes using the app's own colour tokens, buttons and selects. The theme choice is kept after reload.
