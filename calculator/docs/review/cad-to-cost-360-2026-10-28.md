# CAD to COST — 360° review on the local install (28 Oct 2026)

Senior users reported three things: Calculate does not work, the CAD viewer does not work properly after an upload,
and the flow is too complex. This review ran the feature the way the local install runs it (`npm run dev:full`: Vite on
:5174, API on :3002) and drove it in a real browser with only the controls a person can see
(`e2e/.human-cad360.mts`, screenshots per step, every console error and failed request recorded). Three real parts:
the steering knuckle (forging), the PRCR002 stub axle (cast + machined) and the ECU cover (injection moulded). The
existing automated test (`e2e/cad-parts-live.ts`) never saw most of what follows: it switches the first-run wizard
off, clicks hidden buttons by id and answers every question round by round.

## 1. What a user experiences (traced)

| # | Step | What happens | Where |
|---|---|---|---|
| 1 | Open the app | A white first-run tour modal over the dark theme | tour |
| 2 | Home → "Upload CAD — Drop a file or browse" | The card is a plain button: dropping a STEP on it makes the browser download / open the file; "browse" opens the panel, not a file chooser | `index.html:290`, `main.ts:20225` |
| 3 | CAD to COST opens | A "Part Basics" 3-step wizard covers the page and swallows every click (weight, overhead, margin — none of which a CAD costing needs; "Done — Calculate" does not calculate) | `maybeShowWizard` `main.ts:15251` |
| 4 | Upload | The 3D model appears (with the CAD kernel installed). The Analyze buttons are below the 530 px viewer, off-screen; the visible primary button is the green **Calculate** in the bottom bar | `renderCADAnalysisForm` |
| 5 | Press **Calculate** | Nothing is costed. Only a red chip "1 field needs attention"; the reason ("Apply CAD analysis results … 'Apply to cost engine' button") is thrown into a results pane that is hidden on this screen, and names a button that does not exist | `main.ts:14409` |
| 6 | Press **Analyze & Calculate** | The analysis asks which process makes the part (the route is undecided) — but the screen jumps straight to a **Machining** form (the server's fallback route), net weight 0.000, "8 waiting on a decision", "2 fields need attention", and the questions are gone with the CAD panel. No cost | `renderCADResults` `main.ts:6952`; `cad.ts:939` fallback `'machining'` |
| 7 | Press **Analyze Only**, answer the visible questions, press **Apply & Calculate** | New questions arrive one round at a time (knuckle: route + material → tolerance class → safety-critical; stub axle and ECU: 3–4 rounds), each needing **Apply answers & re-cost**. ## 3. Live re-run after the fixes (same three parts, same local install)

The driver (`e2e/.human-cad360.mts … calc-flow`) does what a person does after the upload: press the green **Calculate**,
answer what is asked, press **Get cost**. No wizard, no hidden buttons. UK, 100,000 a year.

| Part | Questions asked (in order) | Presses | Time from Calculate | Cost | Before the fixes |
|---|---|---|---|---|---|
| Steering knuckle | route + material family → tolerance class → safety-critical (stopped on as New) | Calculate + 3 × Get cost | 31 s | **£24.10** ± 8.8 % (£24.09 on the first runs: F19) | Calculate: nothing; Analyze & Calculate: a Machining form at 0.000 kg; £24.09 only after 3 separate Apply rounds |
| PRCR002 stub axle | route + family → safety-critical + pressure-tight (New) → tolerance class (grade now EN-GJS-500-7) | Calculate + 3 × Get cost | 36 s | **£53.06** ± 8.7 % | same as above; £53.06 after 4 rounds |
| ECU cover | route + family → resin → nothing left (ready strip) | Calculate + 2 × Get cost | 23 s | **£1.22** ± 7.2 % (PC/ABS; the earlier £1.50 was PA66 GF30) | same as above |
| ECU cover, PBT GF30 from "Other resin" | as above | Calculate + 1 × Get cost | 26 s | **£1.65** ± 8.5 % | not reachable from the question |

In every run the 3D model sits at the top of the result column (290 px from the top of the window; it was 2,300–5,100 px
down), and Excel and PDF downloaded (0.4–0.9 s). With the CAD kernel switched off (a server started with a Python that has
no OCP) the start-up log says so and the CAD screen shows the notice above the upload before any file is chosen.
The launcher's install path was proven in a scratch copy: no OCP on `python3` → `calculator/.venv-cad` created and
`cadquery-ocp-novtk` installed in 18 s → `PYTHON_BIN` exported.
